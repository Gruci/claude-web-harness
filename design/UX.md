# design/UX.md — UX 원칙·레이블 규칙

> 담는 것: 사용자에게 보이는 문구와 정보 위계의 판단 기준, 금칙 조어. 담지 않는 것: 코드 식별자 이름(→ `dev/NAMING.md`)·시각적 배치(→ `design/LAYOUT.md`). 읽는 시점: 사용자 노출 텍스트를 쓰거나 화면 정보 우선순위를 정할 때.

프로젝트 무관 보편 원칙과 impeccable 디자인 품질 기준을 담는다. 프로젝트 고유 UX 규칙은 확정되는 대로 추가한다.

## 레이블 원칙

- **자기설명 레이블**: 처음 보는 사용자가 설명 없이 이해할 수 있어야 한다.
- **조어 금지**: 마케팅성 신조어·내부용어를 사용자 노출 텍스트에 쓰지 않는다. 리뷰에서 조어 발견 시 `static_check.py`의 `UI_DENYLIST`에 그 문자열을 추가 (다음부터 자동 차단).
- 결측 = `'-'`, 로딩 = `'불러오는 중…'` 통일.
- 이모지 금지 (문서화된 예외만).

## 정보 위계 원칙

- **결론 → 근거 → 상세** 순서: 화면 최상단에 결론(요약), 아래로 근거·상세.
- 핵심 지표가 스크롤 아래 묻히지 않게 배치.
- 지표 옆에 맥락(비교 기준·기간·출처)을 함께 — 숫자 단독 노출 금지 (Footnote).

## 필터·인터랙션 원칙

- 유사 화면끼리 필터 UI·동작 통일 — 한쪽만 개편 금지.
- (프로젝트 고유 규칙 확정 시 추가)

## AI 슬롭 테스트 (impeccable 기반)

누군가 이 인터페이스를 보고 "AI가 만들었네"라고 확신할 수 있으면 실패다.

**카테고리-반사 체크 (2단계):**
1. **1차**: 카테고리만 보고 테마+팔레트를 맞출 수 있으면 → 훈련 데이터 첫 번째 반사. 다시.
2. **2차**: 카테고리 + "안티레퍼런스"로 미학 패밀리를 맞출 수 있으면 → 함정 한 단계 아래. 다시.

## 디자인 품질 기준

- **프로토타입이 아닌 프로덕션 수준** — 완성된 코드, 반응형, 접근성, 버그 없음.
- **세부사항에 진지하게** — 모든 컴포넌트/페이지는 다양한 뷰포트·상태에서 검증.
- `/impeccable critique` — UX 휴리스틱 점수 리뷰
- `/impeccable audit` — 기술 품질(a11y, 성능, 반응형) 점검
- `/impeccable polish` — 출하 전 최종 품질 패스
