# md-audit — MD ↔ 코드 드리프트 감사

> 산문(의미 서술) 부패는 게이트로 못 잡는다. 이 감사가 상한선이다.
> 검사 가능한 항목(경로 실존 등)을 게이트에 추가했다면 여기서 중복하지 않는다 — **이 감사의 대상은 게이트가 못 잡는 의미 서술**이다.

## 실행 절차

1. **게이트 선실행**: `python -X utf8 -m kernel.runner` — 기계 검사분을 먼저 소거.
2. **대상 MD**: CLAUDE.md · DEVGUIDE.md · dev/*.md · design/*.md · 각 도메인 MD · frontend/FRONTEND.md 등 (docs/tasks/·archive 제외).
3. **병렬 팬아웃**: 읽기 전용 에이전트(Explore) 2~4개로 MD 그룹 분담. 각 에이전트 지시:
   - MD의 **모든 사실 주장**(함수 소속·시그니처·동작 서술·파일 구조·개수·필드명)을 코드 실물 Read/Grep으로 대조.
   - 판정: 정확 / stale(코드가 변했는데 MD 미갱신) / 적극적 오류(처음부터 틀림) / 누락(코드에 있는데 MD에 없어 혼동 유발).
   - **오진 방지**: 한 파일만 보고 관례 위반이라 단정 금지 — 형제 파일 관례 증거 수집.
   - **아무것도 수정 금지** — 발견만.
4. **보고서 산출**: `docs/tasks/md_audit_findings_YYYY-MM.md` — 파일별 findings(현재 잘못된 문장 인용 + 교정 방향), 숫자 요약.
5. **자동 수정 금지** — 보고서를 사용자에게 보여주고 수정 여부·범위는 사용자가 결정한다.

## 재발 방지 3층 구조

①손사본 금지(코드 사실은 포인터로 — 예: 라우트 정본은 App.tsx) ②게이트(기계 검사) ③이 월간 감사(의미 서술).
