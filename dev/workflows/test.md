# 테스트 절차

> 담는 것: 테스트 계층 선택과 실행 결과 판정. 담지 않는 것: 테스트 전략 정본(→ `../TESTING.md`). 읽는 시점: 테스트 작성과 실행 시.

## 계층 선택

`../TESTING.md`를 새로 읽고 현재 테스트 배치를 검색한다.

| 대상 | 계층 | 외부 대체 여부 |
|---|---|---|
| `_format_*` 순수 계산 | 단위 테스트 | 없음 |
| `_fetch_*` 조회 | 통합 테스트 | 실제 테스트 DB 사용 |
| 외부 수집 클라이언트 | 외부 경계 테스트 | HTTP만 `monkeypatch`로 대체 |

내부 `_fetch_*`를 가짜로 바꾸고 상위 조회 함수가 검증됐다고 판단하지 않는다.
계산 결과 검증은 순수 함수 테스트에 집중한다.
실제로 없는 테스트 하위 폴더를 관성적으로 만들지 않는다.

## 작성

- 확정된 순수 함수부터 검증하고 자주 바뀌는 임시 구조를 테스트로 고정하지 않는다.
- 새로운 `_format_*` 동작에는 단위 테스트를 추가한다.
- 버그는 재현 테스트를 먼저 작성하고 수정 후 통과를 확인한다.
- 외부 파서는 실제 응답 픽스처로 회귀를 검증한다.
- 테스트 편의를 위한 새로운 HTTP 모킹 의존성을 추가하지 않는다.

## 실행과 보고

- 변경 계약을 증명하는 가장 좁은 계층부터 실행한다.
- Python은 프로젝트 규약에 맞는 대상 테스트를 실행한 뒤 필요한 전체 검사를 실행한다.
- 프론트엔드 변경은 해당 프로젝트의 타입 검사와 빌드 명령을 확인해 실행한다.
- pytest 마커는 설정에 등록된 경우에만 선택 조건으로 쓴다.
- 테스트가 하나도 선택되지 않은 실행을 검증 성공으로 보고하지 않는다.
- 정확한 명령과 종료 코드를 기록한다.
- 실패와 경고 및 실행하지 못한 검사를 구분해 보고한다.
