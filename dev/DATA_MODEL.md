# dev/DATA_MODEL.md — DB 설계도

> 담는 것: 테이블 정의의 정본, 차원과 팩트를 가르는 설계 원칙, 신규 테이블 표준 절차. 담지 않는 것: 컬럼 이름 규칙(→ `dev/NAMING.md`)·레이어 경계(→ `dev/ARCHITECTURE.md`). 읽는 시점: **DB 테이블이나 컬럼을 추가·수정하기 전, 예외 없이.**

아직 스키마가 없다. 첫 테이블 설계 시 아래 절차를 따르고 이 문서에 등재한다. 왜 이 문서가 강제인지는 `dev/LESSONS.md` §9에 있다.

## DB 설계 표준 절차 (테이블/컬럼 추가 전)

1. **이 문서의 테이블 목록을 먼저 확인** — 같은 데이터가 이미 어느 차원/테이블에 있는지. 중복 컬럼 신설 금지.
2. **차원 vs 팩트 구분** — 불변 속성(이름·분류·카테고리)은 차원 테이블 한 곳에만. 측정값(일별 수치)만 팩트 테이블에. 팩트마다 차원 컬럼 denormalize 금지 → JOIN.
3. **확장성 자문** — "카테고리/국가/자산군이 하나 더 들어오면?" 차원 row 추가만으로 끝나야 정상. 팩트마다 컬럼 추가 설계면 틀린 것.
4. **컬럼 네이밍** — `dev/NAMING.md` 준수: 의미 기반 풀네임, 축약어·내부코드 금지. dict 키·API 필드와 동일 규칙.
5. **DDL 위치** — `db/schema.py`의 `init_db()` (멱등 생성). 설계 확정 후 이 문서에 테이블·컬럼·차원/팩트 구분을 등재.

## 공통 규칙

- 날짜 컬럼: `YYYY-MM-DD` 문자열 통일 (`dev/NAMING.md`)
- timestamp: naive 금지 — KST `+09:00` aware (`dev/CONVENTIONS.md` B7)
- 0은 유효값 — NULL로 변환 금지 (B8)
