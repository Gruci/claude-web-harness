AI는 대화가 끝나면 잊습니다. 다음 세션의 AI는 앞의 약속을 모른 채 자기 스타일로 새로 짭니다. 그게 쌓이면 아무도 못 읽는 코드가 됩니다.

문서에 "이렇게 하세요"라고 적어두는 걸로는 부족합니다. 사람도 AI도 글로만 있는 규칙은 쉽게 넘어갑니다.

그래서 이 하네스는 부탁하지 않습니다. 설계를 먼저 받아내고, 지켰는지는 기계가 잽니다. 어기면 통과가 안 됩니다.

## 시작하기

```bash
git clone https://github.com/WooriGrunda/claude-web-harness.git my-project
cd my-project
rm -rf .git && git init && git add -A && git commit -m "init"
claude
```

그리고 **"하네스 깔아줘"** 라고 하면 됩니다.

설치할 때 물어보는 건 한 가지입니다. 무엇을 만들 건지.

> - 사람이 브라우저로 쓰는 것 — 로그인하고, 화면 보고, 버튼 누른다
> - 다른 프로그램이 부르는 것 — 화면 없이 데이터만 주고받는다
> - 혼자 시간표대로 도는 것 — 크롤링, 집계, 리포트 생성
> - 아직 모르겠다

여기 답하면 나머지는 알아서 합니다. 어떤 기술을 쓸지 골라서 이유와 함께 알려주고, 설정을 채우고, GitHub 비공개 저장소를 만들어 올리고, 마지막에 지금부터 무엇이 막히는지 알려줍니다.

**기술 이름은 몰라도 됩니다.** "FastAPI 쓸래 Django 쓸래" 같은 건 묻지 않습니다. "아직 모르겠다"를 골라도 됩니다 — 가장 흔한 쪽으로 깔아두고, 안 쓰는 부분은 그냥 꺼집니다.

사람이 직접 클릭할 건 둘뿐입니다. 새 폴더를 믿을지 확인하는 창, 그리고 그 컴퓨터에서 처음 한 번 뜨는 동의 창. Claude Code 자체 안전장치라 하네스가 없앨 수 없습니다.

## 하루가 어떻게 흘러가나

"대시보드 만들어줘"라고 하면 코딩부터 시작하지 않습니다.

**묻습니다.** 어느 화면에 넣을지, 무슨 데이터를 쓸지, 어디까지 만들지.

**읽습니다.** 관련 코드를 직접 봅니다. 파일명만 훑지 않습니다. 데이터가 어디서 와서 어디로 가는지까지 봅니다.

**씁니다.** 설계서를 파일로 남깁니다. 정확한 파일 경로, 실제 코드 조각, 무엇이 깨질 수 있는지. "나중에 구현"이나 "위와 비슷하게" 같은 빈칸이 있으면 설계서로 인정하지 않습니다. 화면이면 PC 배치와 폰 배치가 둘 다 있어야 합니다.

**멈춥니다.** 당신이 읽고 승인할 때까지. 여기까지 코드는 한 줄도 건드리지 않습니다.

**짭니다.** 승인된 설계서대로. 저장할 때마다 검사가 돌고, 어기면 그 자리에서 막힙니다.

**치웁니다.** 관련 문서를 갱신하고 작업 파일을 정리합니다. 대화를 끝내려 하면 전체 검사가 다시 돕니다. 하나라도 남아 있으면 대화가 끝나지 않습니다.

기능 하나를 만드는 동안 당신이 입을 여는 건 두 번입니다. 질문에 답할 때, 그리고 설계서를 승인할 때. 그 사이는 알아서 갑니다.

## 무엇이 막히나

파일을 저장하는 순간 검사가 돕니다. 예를 들면 이런 것들입니다.

| 이렇게 쓰면 | 이렇게 막힙니다 |
|:--|:--|
| 조회 전용 폴더에 데이터를 지우는 코드 | 그 자리에서 차단 |
| 화면 파일에 색상값 `#ff8800` 직접 입력 | 색은 정해둔 한 곳에서만 |
| 폰에서 깨지는 고정 너비 `width: 420px` | 화면 크기에 맞춰 늘어나는 방식으로 |
| 한 파일이 400줄 초과 | 기능 단위로 나누라고 |
| API 키를 코드에 그대로 | 설정 파일 거쳐서 |
| 문서에 적은 파일 경로가 실제로 없음 | 문서를 고치라고 |

이런 검사가 서른 가지 있습니다. 대화를 끝내려 할 때 전부 한 번 더 돌고, 하나라도 걸리면 대화가 안 끝납니다.

### 안 하는 검사는 안 한다고 말합니다

이 하네스에서 제일 중요한 부분입니다.

검사에 필요한 정보를 안 알려주면 통과로 처리하지 않습니다. 이렇게 찍힙니다.

```
[SKIP] 브라우저 API 직접 호출 — 설정에 브라우저 API 래퍼를 안 적었음
```

"이 검사는 지금 아무것도 안 보고 있습니다"라는 뜻입니다. 통과가 아닙니다.

예전 버전은 이걸 그냥 통과로 처리했습니다. 그래서 폴더 이름 하나가 설정과 안 맞으면 여덟 개 검사가 아무 일도 안 하면서 초록불을 냈습니다. **지켜주지 않는 것을 지켜준다고 믿는 게 제일 위험합니다.**

## 이미 코드가 있는 프로젝트에 얹을 때

기존 코드에 얹으면 첫 검사에서 수백 건이 쏟아질 수 있습니다. 그러면 사람은 검사를 통째로 꺼버립니다. 이런 도구가 죽는 흔한 경로가 그겁니다.

그래서 설치할 때 **지금 있는 문제는 "원래 있던 것"으로 적어두고 넘어갑니다.** 그 목록은 늘어나지 않습니다. 해당 파일을 다음에 손볼 때 고치고 목록에서 지우면 됩니다. 새로 만드는 파일은 처음부터 전부 통과해야 합니다.

복제하지 않고 파일만 가져올 때는 `kernel/`·`profiles/`·`.claude/`·`harness_install.py`를 복사하고 `.claude/settings.json`의 `hooks` 부분만 합칩니다.

## 안 맞으면 바꾸면 됩니다

폴더 이름, 검사 켜고 끄기, 줄 수 제한. 전부 `harness_profile.py` 한 파일에서 정합니다. 다른 프로젝트로 옮길 때 고치는 파일도 이거 하나입니다.

`api/` 폴더를 쓰는 프로젝트면 `"web": "api"`라고 적으면 됩니다. 화면이 없으면 화면 항목을 비우고, 그러면 화면 검사 여섯 개가 꺼집니다. 나중에 화면을 붙이기로 하면 그 한 줄을 적는 순간 다시 켜집니다.

설정과 실제 폴더가 어긋나면 검사가 잡습니다. 선언 안 한 폴더에 코드를 만들면 저장하는 순간 막히고, 설치할 때도 한 번 짚어줍니다. 그래도 놓치면 꺼진 검사가 위처럼 `[SKIP]`으로 보입니다.

## 정기 점검

프로젝트가 자라면 문서가 코드와 어긋나고, 코드가 필요 이상 복잡해지고, "나중에 보강"이라고 표시해둔 게 쌓입니다.

**외울 명령이 없습니다.** 하네스가 세고 있다가 때가 되면 세션 시작할 때 알려주고, 하던 일을 끝낸 뒤 알아서 돌립니다. 문서와 코드가 어긋난 곳, 필요 이상으로 복잡한 코드, 미뤄둔 것들, 화면 사용성, 사용자 관점의 지표와 문구. 다섯 가지입니다.

전부 보고서만 내고 코드는 건드리지 않습니다. 그래서 물어보지 않고 돌립니다. 결과를 보고 고칠지는 그다음에 정하면 됩니다. 화면이 없는 프로젝트에서는 화면 관련 두 가지가 아예 안 뜹니다.

주기가 안 맞으면 `harness_profile.py`에서 조정합니다.

## 검사가 늘어나는 방식

검사는 처음부터 설계한 게 아닙니다. 사고가 날 때마다 하나씩 늘었습니다.

사고가 나면 먼저 경위를 `dev/LESSONS.md`에 적습니다. 무슨 일이 있었고 무엇을 잃었는지. 규칙만 적어두면 다음 세션이 "이번은 예외 아닌가" 하고 넘어가지만, 대가가 적혀 있으면 못 넘어갑니다.

그다음 기계가 검사할 수 있는 규칙인지 봅니다. 할 수 있으면 검사로 만듭니다. 그때부터 그 규칙은 부탁이 아니라 차단입니다. 못 만들면 "글로만 남긴다"고 이유를 적습니다. 둘 중 아무것도 안 적으면 검사가 잡습니다. 적어놓고 판단을 미룬 상태니까요.

그래서 글로만 남은 목록이 곧 다음에 검사로 만들 후보입니다.

오래 굴릴수록 그 프로젝트에서 실제로 났던 사고에 맞게 촘촘해집니다. 남의 베스트 프랙티스가 아니라 우리가 당한 것들로 채워집니다.

## 어떤 모델이 무슨 일을 하나

모델에는 급이 있습니다. 깊게 생각하지만 비싼 것과, 빠르고 싼 것. 판단은 위로 올리고 손 많이 가는 일은 아래로 내린 뒤 요약만 받습니다.

**Opus**가 설계하고 판단하고 검수합니다. 서비스가 복잡해질수록 설계가 어려워집니다. 이 자리는 급을 낮추지 않습니다.

**Fable**은 승인된 설계서를 통째로 구현합니다. 판단이 끝났고 남은 게 손일 때 씁니다. 설계서에 빈칸이 있으면 멋대로 채우지 않고 멈춰서 되돌려 보냅니다.

**Sonnet**은 수십 개 파일을 읽고 대조하는 일을 나눠 맡고 요약만 올립니다.

이 배정도 검사가 지킵니다. 몰래 싼 모델로 바꿔치기하면 대화가 끝나지 않습니다.

## 안에 뭐가 들었나

| 파일 | 역할 |
|:--|:--|
| `CLAUDE.md` | AI 행동 규칙. 세션마다 자동으로 읽힘 |
| `PROJECT.md` | 이 프로젝트가 무엇인지. 다루는 분야, 용어, 폴더 구조 |
| `HARNESS.md` | 검사·자동 실행 스크립트·담당 AI 전체 지도 |
| `DEVGUIDE.md` · `DESIGN_GUIDE.md` | 서버 규칙 → `dev/`, 화면 규칙 → `design/` |
| `EDITING.md` | 작업 현황판. 여러 세션이 같은 파일을 건드리는 걸 막음 |
| `harness_profile.py` | 이 프로젝트의 폴더 이름과 용어. 설정은 여기 하나 |
| `harness_install.py` | 설치 스크립트 |
| `kernel/` | 검사 로직. 프로젝트가 뭔지 모름 |
| `profiles/` | 만들려는 것에 따라 고르는 설정 서식 |
| `tests/` | 검사기 자신이 망가졌는지 확인하는 장치 |
| `.claude/` | 자동 실행 스크립트, 담당 AI, 작업 절차 |
| `AGENTS.md` · `.agents/` · `.codex/` | 다른 AI 도구(Codex)용. Claude는 안 읽음 |

검사 로직은 프로젝트를 모르고, 프로젝트 사정은 설정 파일 하나에만 있습니다. "조회 전용 폴더에서 데이터를 지우면 안 된다"는 판단은 검사 로직에 있고, 그 폴더가 어디인지는 설정이 정합니다. 그래서 같은 검사기가 어떤 기술 조합에도 얹힙니다.

이 프로젝트에서만 참인 규칙은 검사기 본체가 아니라 `harness_gates/`에 따로 심습니다. 검사기가 남의 프로젝트 사정을 이고 다니지 않게 하려는 겁니다.

## 검사기 자신은 누가 검사하나

`tests/`에 일부러 위반을 하나씩 심어둔 가짜 프로젝트와, 그걸 검사한 결과 정답지가 들어 있습니다.

```bash
python -X utf8 tests/run_golden.py
```

지금 결과를 정답지와 대조합니다. 검사기를 고치다가 어떤 검사가 조용히 약해지면 그 줄이 바로 나옵니다.

## 자주 묻는 것

**git이 꼭 있어야 하나요?** 네. 검사가 git이 관리하는 파일 목록을 기준으로 돕니다. git이 없으면 검사할 대상 자체를 못 찾으니, 통과가 아니라 "지금 git 부터 만드세요"로 막습니다.

**GitHub 저장소도 만들어야 하나요?** 만들어줍니다. `gh` 명령으로 GitHub에 로그인만 돼 있으면 비공개 저장소를 알아서 만들고 올립니다. 폴더 이름이 저장소 이름이 됩니다. 공개 저장소는 되돌리기 어려워서 그것만 직접 말해야 합니다. 로그인이 안 돼 있으면 그때만 물어봅니다.

**나중에 만들려는 게 바뀌면요?** 화면 없이 시작했다가 화면을 붙이는 건 설정 한 줄입니다. 반대도 같습니다.

**그래서 사람이 채우는 건 뭔가요?** 설치할 때는 없습니다. 폴더 이름과 프레임워크 함수 이름 몇 개가 필요한데 전부 대신 채워줍니다.

사람만 아는 건 **이 서비스가 다루는 분야의 지식**뿐이고 `PROJECT.md`에 들어갑니다. 무엇을 다루는지, 어떤 용어를 쓰는지, 어떤 숫자가 의미 있는지. 그것도 미리 다 채우는 게 아니라 개발하면서 쌓입니다.

**나중에 앱으로 만들 수도 있나요?**

<details>
<summary>화면을 만드는 프로젝트라면 미리 해두는 것들</summary>

지금 개발은 웹 기준입니다. 다만 나중에 앱으로 옮길 때 가져갈 것과 버릴 것이 정해져 있어서, 가져갈 것을 처음부터 분리해둡니다.

| 규칙 | 앱으로 옮길 때 |
|:--|:--|
| 계산과 데이터 가공은 화면 파일 밖에 | 로직은 그대로 이동 |
| 색·간격·글자 크기는 정해둔 파일에서만 | 값 그대로 재사용 |
| 브라우저 전용 기능은 파일 하나를 거쳐 | 그 파일 하나만 교체 |
| 페이지 이동 코드는 페이지 단계에만 | 교체 범위 최소 |

앱이 필요해지면 화면만 다시 만듭니다. 서버와 로직과 디자인 값은 그대로 갑니다. 앱을 영영 안 만들어도 손해는 없습니다. 이 분리는 그 자체로 좋은 구조이기 때문입니다.

화면은 설계 단계에서 PC와 폰을 함께 확정한 뒤에만 승인됩니다. 만들고 나서 "모바일도"는 뜯어고치는 일이지만, 설계 때 정하면 그냥 설계입니다.
