# claude-web-harness

**먼저 묻습니다. 설계부터 씁니다. 어기면 막습니다.**

스택 무관 커널 + 프로파일 &nbsp;·&nbsp; 하네스 v3.0.0

[한국어](README.md) · [English](README.en.md)

AI는 대화가 끝나면 잊습니다. 다음 세션의 AI는 앞의 약속을 모른 채 자기 스타일로 새로 짭니다. 그게 쌓이면 아무도 못 읽는 코드가 됩니다.

문서에 "이렇게 하세요"라고 적어두는 걸로는 부족합니다. 사람도 AI도 글로만 있는 규칙은 넘기기 쉽습니다.

그래서 이 하네스는 부탁하지 않습니다. 설계를 먼저 받아내고, 지켰는지는 기계가 잽니다. 어기면 통과가 안 됩니다.

이 저장소가 그 배포본입니다. 어느 프로젝트에 떠 가도 아래 설치만 하면 바로 시작합니다.

## 어떻게 도나요

"대시보드 만들어줘"라고 하면 AI는 코딩부터 시작하지 않습니다.

**묻습니다.** 어느 화면에 넣을지, 무슨 데이터를 쓸지, 어디까지 만들지.

**읽습니다.** 관련 코드를 직접 봅니다. 파일명만 훑지 않습니다. 데이터가 어디서 와서 어디로 가는지까지 봅니다.

**씁니다.** 설계서를 파일로 남깁니다. 정확한 파일 경로, 실제 코드 조각, 무엇이 깨질 수 있는지. "나중에 구현"이나 "위와 비슷하게" 같은 빈칸이 있으면 설계서로 인정하지 않습니다. 화면이면 PC 배치와 폰 배치가 둘 다 있어야 합니다.

**멈춥니다.** 당신이 읽고 승인할 때까지. 여기까지 코드는 한 줄도 건드리지 않습니다.

**짭니다.** 승인된 설계서대로. 저장할 때마다 검사가 돌고, 어기면 그 자리에서 막힙니다.

**치웁니다.** 관련 문서를 갱신하고 작업 파일을 정리합니다. 대화를 끝내려 하면 전체 검사가 다시 돕니다. 하나라도 남아 있으면 대화가 끝나지 않습니다.

당신이 입을 여는 건 두 번입니다. 질문에 답할 때와 설계서를 승인할 때.

## 설치

```bash
git clone https://github.com/WooriGrunda/claude-web-harness.git my-project
cd my-project
rm -rf .git && git init && git add -A && git commit -m "init"
claude
```

그리고 **"하네스 깔아줘"** 라고 하면 됩니다. 나머지는 알아서 합니다 — 무엇을 만들 건지 한 번
묻고, 스택을 골라서 이유와 함께 알려주고, 설정 파일을 채우고, GitHub 비공개 레포를 만들어
푸시하고, 꺼진 검사가 없는지 확인하고, 무엇이 지금부터 막히는지 사람 말로 알려줍니다.

**사람이 답할 건 하나입니다** — 무엇을 만들 건지. 나머지는 물어보지 않습니다.

**스택을 몰라도 됩니다.** 물어보는 건 "FastAPI 쓸래 Django 쓸래"가 아니라 "사람이 브라우저로
쓰는 건가요, 시간표대로 도는 건가요"입니다.

이미 있는 프로젝트에 얹을 때는 복제 대신 `kernel/`·`profiles/`·`.claude/`·`harness_install.py`
만 복사하고 `.claude/settings.json` 의 hooks만 합칩니다. **기존 코드가 많아도 한꺼번에 터지지
않습니다** — 설치가 지금 있는 문제를 "원래 있던 것"으로 기록하고, 그 목록은 줄어들기만 합니다.

**기존 코드가 많아도 한꺼번에 터지지 않습니다.** 설치 스크립트가 지금 있는 문제를 "원래 있던 것"으로 기록합니다. 그 목록은 줄어들기만 합니다. 새로 만드는 파일은 처음부터 전부 통과해야 합니다.

**git과 원격은 선택이 아닙니다.** 검사가 git이 관리하는 파일 목록을 기준으로 돕니다. git이 없으면 검사가 불가능하니, 통과가 아니라 "지금 git init 하세요"로 막습니다. 원격이 없으면 코드가 그 컴퓨터에만 있는 셈이라, 연결될 때까지 대화를 끝낼 수 없습니다.

이것도 손댈 게 없습니다. `gh` 로 GitHub에 로그인만 돼 있으면 **비공개 레포를 알아서 만들고 푸시합니다.** 폴더 이름이 레포 이름이 됩니다. 공개 레포는 되돌리기 어려워서 그것만 직접 말해야 합니다. 로그인이 안 돼 있으면 그때만 물어봅니다.

사람이 클릭할 건 둘뿐입니다. 새 폴더 신뢰 확인, 그리고 그 컴퓨터에서 위험 모드 첫 동의. Claude Code 자체 안전장치라 하네스가 없앨 수 없습니다.

## 쓰는 법

평소 말투로 부탁하면 됩니다. 외울 명령어는 없습니다.

```
대시보드 페이지 만들어줘
이 버그 고쳐줘
API 추가해줘
```

서버와 화면을 같이 만들어야 하면 담당 둘을 동시에 돌립니다. 서로 주고받는 데이터가 맞는지까지 잽니다.

## 하네스가 자라는 법

게이트는 처음부터 설계한 게 아닙니다. 사고가 날 때마다 하나씩 늘었습니다.

사고가 나면 먼저 경위를 `dev/LESSONS.md` 에 남깁니다. 무슨 일이 있었고 무엇을 잃었는지. 규칙만 적으면 다음 세션이 "이번은 예외 아닌가" 하고 넘기지만, 대가가 적혀 있으면 못 넘깁니다.

그다음 기계가 검사할 수 있는지 봅니다. 할 수 있으면 게이트로 올립니다. 그때부터 그 규칙은 부탁이 아니라 차단입니다. 못 올리면 "산문 전용"이라고 이유를 적습니다. 둘 중 아무것도 안 적으면 검사가 잡습니다. 적어놓고 판단을 미룬 상태니까요.

그래서 산문 전용으로 남은 목록이 곧 다음에 게이트로 올릴 후보입니다.

프로젝트를 오래 굴릴수록 그 프로젝트에서 실제로 났던 사고에 맞게 촘촘해집니다. 남의 베스트 프랙티스가 아니라 우리가 당한 것들로 채워집니다.

## 무엇이 들어 있나요

**게이트 30종.** 저장할 때와 대화를 끝낼 때 도는 검사입니다. 파일당 400줄, 이름 짓는 방식, 정해둔 폴더 밖에 코드 만들기 금지, 화면 파일에 색상값 직접 쓰기 금지, 폰을 깨뜨리는 고정 폭 금지, 문서에 적힌 경로가 실제로 있는지, 어떤 일에 어떤 모델을 쓸지까지. 전부 켠 채로 출발합니다. 조정은 `harness_profile.py` 한 곳에서 합니다.

**꺼진 검사는 꺼졌다고 말합니다.** 검사에 필요한 정보를 안 알려줬으면 통과가 아니라
`[SKIP] 브라우저 API 직접 호출 — 프로파일에 래퍼 미선언` 처럼 이유와 함께 찍힙니다.
이전 세대는 이걸 그냥 통과로 처리했고, 그래서 폴더 이름 하나가 안 맞으면 여덟 개 검사가
아무것도 안 하면서 초록불을 냈습니다. **지켜주지 않는 것을 지켜준다고 믿는 게 제일 위험합니다.**

**훅.** 정해진 순간에 자동으로 뛰는 스크립트입니다. 저장 직후, 대화 종료 직전, 세션 시작. `.claude/hooks/` 에 있고 언제 뭘 뛸지는 `.claude/settings.json` 이 정합니다.

**에이전트.** 분야를 전담하는 일꾼입니다. 서버, 화면, 검증. 각자 자기 규칙 문서를 먼저 읽고 일합니다. `.claude/agents/` 에 있습니다.

**스킬.** 자주 하는 작업의 순서를 묶어둔 것입니다. "기능 만들어줘" 한마디에 인터뷰부터 정리까지의 순서가 켜집니다. `.claude/skills/` 에 있습니다.

**문서.** 규칙과 이 프로젝트만의 지식이 쌓이는 곳입니다. AI는 세션마다 `CLAUDE.md` 를 자동으로 읽습니다. 전체 지도는 `HARNESS.md`, 서버는 `DEVGUIDE.md`, 화면은 `DESIGN_GUIDE.md` 입니다.

## 계층

```text
사람
 └─ Claude Code 세션
     ├─ 스킬
     ├─ 에이전트
     └─ 훅
         └─ kernel/  (판정 로직 — 프로젝트를 모릅니다)
             └─ harness_profile.py  (이 프로젝트의 이름과 어휘)
```

아래가 위를 강제합니다. 사람이 어겨도 훅이 막고, 훅이 무엇을 막을지는 설정 파일 하나가 정합니다. 그래서 다른 프로젝트로 옮길 때 고치는 파일도 `harness_profile.py` 하나입니다.

**커널은 규칙을 갖지 않고 규칙의 형태만 갖습니다.** "읽기 전용 폴더에서 쓰기를 하면 안 된다"는
판정은 커널에 있고, 그 폴더가 어디인지는 프로파일이 정합니다. 그래서 같은 커널이 어떤 스택에도
얹힙니다. 이 프로젝트에서만 참인 규칙은 커널이 아니라 `harness_gates/` 에 심습니다 — 커널이
남의 프로젝트 규칙을 이고 가지 않게 하려는 겁니다.

## 비용

모델에는 급이 있습니다. 깊게 생각하지만 비싼 것과, 빠르고 싼 것. 판단은 위로 올리고 손 많이 가는 일은 아래로 내린 뒤 요약만 받습니다.

**Opus** 가 설계하고 판단하고 검수합니다. 서비스가 복잡해질수록 설계가 어려워집니다. 이 자리는 급을 낮추지 않습니다.

**Fable** 은 승인된 설계서를 통째로 구현합니다. 판단이 끝났고 남은 게 손일 때 씁니다.

**Sonnet** 은 수십 개 파일을 읽고 대조하는 일을 나눠 맡고 요약만 올립니다.

이 배정도 게이트가 지킵니다. 몰래 싼 모델로 바꿔치기하면 대화가 끝나지 않습니다. 큰 공사를 맡은 Fable은 설계서에 빈칸이 있으면 멋대로 채우지 않습니다. 멈추고 되돌려 보냅니다.

## 모바일과 앱

화면은 설계 단계에서 PC와 폰을 함께 확정한 뒤에만 승인됩니다. 만들고 나서 "모바일도"는 뜯어고치는 일이지만, 설계 때 정하면 그냥 설계입니다. 폰을 깨뜨리는 흔한 원인은 저장하는 순간 막히고, 완성이라고 말하기 전에 390px에서 안 깨지는지 확인해야 합니다.

지금 개발은 100% 웹입니다. 다만 나중에 앱으로 옮길 때 가져갈 것과 버릴 것이 정해져 있어서, 가져갈 것을 처음부터 분리해둡니다.

| 규칙 | 앱으로 옮길 때 |
|:--|:--|
| 계산과 데이터 가공은 화면 파일 밖에 | 로직은 그대로 이동 |
| 색·간격·글자 크기는 상수 파일에서만 | 값 그대로 재사용 |
| 브라우저 전용 기능은 파일 하나를 거쳐 | 그 파일 하나만 교체 |
| 페이지 이동 코드는 페이지 단계에만 | 교체 범위 최소 |

앱이 필요해지면 화면만 다시 만듭니다. 서버와 로직과 디자인 값은 그대로 갑니다. 앱을 영영 안 만들어도 손해는 없습니다. 이 분리는 그 자체로 좋은 구조이기 때문입니다.

## 정기 점검

**외울 명령이 없습니다.** 때가 되면 알아서 돕니다.

프로젝트가 자라면 문서가 코드와 어긋나고, 코드가 필요 이상 복잡해지고, "나중에 보강"이라고
표시해둔 것이 쌓입니다. 하네스가 그걸 셉니다 — 마지막 점검 이후 커밋이 몇 개인지, 화면
파일이 몇 개 바뀌었는지, 미뤄둔 표시가 몇 개인지. 임계치를 넘으면 세션을 시작할 때 알리고,
하던 일을 끝낸 뒤 알아서 돌립니다.

| 점검 | 언제 |
|:--|:--|
| 문서와 코드가 어긋난 곳 | 커밋 80개 또는 한 달 |
| 필요 이상으로 복잡한 코드 | 커밋 150개 또는 두 달 |
| 미뤄둔 것 수확 | 표시가 12개 쌓이면 |
| 화면 사용성 점검 | 화면 파일 20개가 바뀌면 |
| 사용자 관점 검수 | 화면 파일 12개가 바뀌면 |

**전부 보고서만 내고 코드는 건드리지 않습니다.** 그래서 물어보지 않고 돌립니다. 결과를 보고
고칠지는 그다음에 정하면 됩니다. 화면이 없는 프로젝트에서는 화면 관련 두 항목이 아예 안 뜹니다.

주기가 안 맞으면 `harness_profile.py` 의 `MAINTENANCE` 에서 조정합니다.

## 자주 묻는 것

**어떤 스택을 써야 할지 모르겠는데요?** 안 정해도 됩니다. 물어보는 건 만들려는 것이지 기술 이름이 아닙니다.

> 무엇을 만드나요?
> - 사람이 브라우저로 쓰는 것 — 로그인하고, 화면 보고, 버튼 누른다
> - 다른 프로그램이 부르는 것 — 화면 없이 데이터만 주고받는다
> - 혼자 시간표대로 도는 것 — 크롤링, 집계, 리포트 생성
> - 아직 모르겠다

여기 답하면 스택을 **골라서 이유와 함께 알려줍니다.** "FastAPI 와 React 로 가겠습니다, 파이썬 쪽에서 가장 흔한 조합이라 막혔을 때 검색해서 나오는 답이 많습니다" 같은 식입니다. 마음에 안 들면 그때 말하면 됩니다.

"아직 모르겠다"를 골라도 됩니다. 가장 흔한 경우로 깔아두고, 나중에 안 쓰는 부분은 그냥 꺼집니다. 잘못 골라서 손해 보는 구조가 아닙니다.

**나중에 마음이 바뀌면요?** 화면 없이 시작했다가 화면을 붙이는 건 프로파일 한 줄입니다. 그 줄을 적는 순간 화면 검사 6종이 켜집니다. 반대도 같습니다.

**폴더 이름을 바꾸고 싶은데요?** 바꾸면 됩니다. `harness_profile.py` 의 `LAYERS` 에서 정합니다. `api/` 를 쓰는 레포면 `"web": "api"` 로 적으면 됩니다.

선언과 실물이 어긋나면 게이트가 잡습니다. 선언 안 된 폴더에 앱 코드를 만들면 저장하는 순간 막히고, 설치 스크립트도 선언 밖 코드 폴더를 한 번 짚어줍니다. 그래도 놓치면 **꺼진 검사가 `[SKIP]` 으로 보입니다** — 조용히 통과하는 경로가 없습니다.

**특정 검사가 우리한텐 안 맞으면요?** 해당 항목을 프로파일에서 비우면 `[SKIP]` 으로 꺼집니다. 화면이 없는 프로젝트에서 화면 검사가 꺼지는 건 정상입니다. 다만 꺼졌다는 사실은 매번 화면에 나옵니다.

**그래서 사람이 채우는 건 뭔가요?** 설치할 때는 없습니다. 폴더 이름과 프레임워크 함수 이름 몇 개가 필요한데 전부 대신 채워줍니다. 사람만 아는 건 **이 서비스가 다루는 분야의 지식**뿐이고 `PROJECT.md` 에 들어갑니다. 무엇을 다루는지, 어떤 용어를 쓰는지, 어떤 숫자가 의미 있는지. 그것도 미리 다 채우는 게 아니라 개발하면서 쌓입니다.

**검사기가 망가지면 어떻게 아나요?** `tests/` 에 위반을 하나씩 심어둔 가짜 프로젝트와 그 검사 결과 정답지가 있습니다. `python -X utf8 tests/run_golden.py` 가 지금 결과를 정답지와 대조하므로, 리팩터 중에 검사가 조용히 약해지면 그 줄이 diff 로 나옵니다.
