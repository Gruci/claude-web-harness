## 🚦 worktree 병렬 프로토콜 (2026-07-20 체제 전환 — 구 "Git 조작 직렬화" 폐기)

> 구체제 실사고 3건(add -A 쓸어담기·잠금 데드락·브랜치 오염 직전)의 공통 원인 = 워킹트리 1개 공유.
> 해법은 잠금 세분화가 아니라 **격리**: 세션마다 자기 worktree. 파일 충돌은 git 머지가 줄 단위로 판정.

**공유 메인 체크아웃(D:\0.Python\fund_monitor) = main 고정, 구현 금지 구역.**
리서치 Read·로컬 서버 실행·DB 조회 전용. 여기서 브랜치 전환·커밋·소스 편집 금지.

**모든 구현은 자기 worktree 에서:**
1. **착수**: 아래 과업 보드 확인 — 같은 화면·같은 API 계약·동시 편집 위험 파일(web/app.py·db/core.py·db/__init__.py)을 건드리는 진행 중 과업이 있으면 조율(순차) 후 시작. 보드에 행 등록(**#sid 필수** — 자기 scratchpad 경로의 UUID 앞 8자).
2. **격리**: `EnterWorktree` 툴을 쓴다. 만들어지는 자리는 **레포 안 `.claude/worktrees/<이름>`** 이고
   세션 종료 시 툴이 제거를 물어본다 — 잔재 청소가 사람 기억에 안 달린다는 게 이 방식의 값이다.
   수동으로 만들 때도 **같은 자리**에 만든다:
   `git worktree add .claude/worktrees/<이름> -b <브랜치> origin/main`
   브랜치 네이밍: `feat/` `fix/` `perf/` `chore/` `docs/` (툴이 붙이는 `worktree-` 접두는 `git branch -m` 으로 고친다)
   ⚠️ 구 경로 `D:\0.Python\fund_monitor.worktrees\` 는 폐기다(2026-08-04). 툴 기본값과 갈려 있어
   같은 레포의 작업 사본이 두 군데로 흩어졌고, "지금 누가 뭘 하는지" 훑을 때 한 곳만 보면 틀렸다.
   레포 안이어도 게이트·검색에 안 섞인다 — `static_check.py` 는 `git ls-files` 로 파일을 모으고
   `.claude/worktrees/` 는 `.git/info/exclude` 에 등재돼 있다(2026-08-04 실측).
3. **구현·검증**은 전부 worktree 안에서 — 게이트(static_check)·pytest·빌드 동일 적용.
3-1. **서브에이전트는 격리하지 않는다** — 비격리 서브에이전트는 부모의 worktree 를 cwd 로 상속한다.
   `isolation:"worktree"` 를 주면 워커마다 브랜치가 갈라져 이 프로토콜의 브랜치 1개 계약이 깨진다.
   한 worktree 공유라 git 이 파일 충돌을 못 잡는다 — 소유권 배정이 유일한 방어다.
   병렬 구현을 위임하기 직전 베이스라인 커밋을 만든다. 워커 부분 실패 시 선별 롤백의 기준점이다.
4. **완료**: push → `gh pr create` → **CI(PR checks) 통과 확인** → `gh pr merge --merge` → 보드 행 제거.
   머지 충돌 시 자기 브랜치에 main 을 merge 해 해소 후 재푸시 (공유 트리 건드리지 말 것).
5. **잔가지 제거**: `git worktree remove` → `git branch -d <브랜치>` 순서다.
   순서가 계약이다 — worktree 가 점유 중인 브랜치는 로컬 삭제가 거부된다.
   원격 브랜치는 레포 `deleteBranchOnMerge` 설정이 머지 시 자동 삭제한다 — `push --delete` 는 불필요하다.
   빠뜨리면 `git branch -a` 가 죽은 브랜치로 차서 진행 중 과업을 못 가린다.
6. **"깃에 올려라" = push+PR+CI 통과 시 merge 까지 한 번에** (main 직푸시 폐기 — 배포는 merge 가 트리거).
7. 빌드 산출물(`web/static/assets/`·`index.html`)은 **커밋 금지**(gitignore) — 배포 시 서버가 빌드. 로컬 확인용 빌드는 지금처럼 자유.
