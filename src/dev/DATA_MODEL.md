# dev/DATA_MODEL.md — 데이터 모델 설계도

> 담는 것: 테이블을 신설·변경하기 전에 지켜야 할 설계 원칙과, 각 테이블이 **무엇을 담는 차원/팩트인지 + 그 도메인의 함정**. 담지 않는 것: 컬럼 목록과 DDL(→ `db/schema_*.py`)·조회 함수와 접속 절차(→ `db/DB.md`). 읽는 시점: **테이블·컬럼을 추가하거나 고치기 전(예외 없음)**.

`db/` 코드를 어떻게 붙이는지(레이어 경계·절차·인덱스 교훈·SQL 함정)는 `db/DB.md` 가 정본이다. 두 문서는 짝이다.

---

## ⚠️ DB 설계 표준 절차 (데이터 추가 전 필독)

> 이 DB 는 점점 **다른 나라·자산군 데이터가 물린다**(KR 증시 → 미국 NASDAQ/NYSE → …).
> "지금 KR만 있으니까" 식의 단기 설계 금지 — 나라 하나 늘 때마다 N개 테이블을 마이그레이션하는 사태를 만든다.

1. **설계도 먼저 읽기** — 같은/유사 데이터가 이미 어느 테이블·차원에 있는지 이 문서에서 확인. 중복 컬럼 신설 금지.
2. **차원 vs 팩트 구분** — 종목의 *불변 속성*은 차원 한 곳에만, *일별 측정값*은 팩트 테이블에. ↓ 아래 원칙 절.
3. **확장성 자문** — "나라/자산군 하나 더 들어오면?" 차원 row 추가만으로 끝나야 정상. 팩트마다 컬럼을 추가하게 설계됐으면 틀린 것.
4. **컬럼 네이밍** — `dev/NAMING.md` 준수. 의미 기반 풀네임, 축약어·내부코드 금지. DB 컬럼도 dict 키·API 필드와 같은 규칙.
5. **읽기/쓰기 분리** — 조회는 `db/reads/`, 적재는 `db/writes/`(정본 `dev/ARCHITECTURE.md`).

## 종목 차원-팩트 설계 원칙 ★

> **결정: `market`/`country` 는 종목(security)의 속성이므로 `stock_master` 단일 차원에만 둔다. 팩트 테이블은 JOIN 으로 끌어쓴다. 팩트마다 denormalize 금지.**

**왜:**
- `market` 은 날짜마다 안 변한다. 종목의 *불변 속성*이지 *일별 fact 행의 속성*이 아니다. 매 팩트에 복제하면 같은 종목의 market 이 여러 곳에 저장돼 drift 와 누락이 생긴다.
- **나라 추가 = `stock_master` row insert 만.** 차원 한 곳에 넣으면 movers·공매도·수급·시장폭이 JOIN 으로 market/country 를 자동 상속한다. 팩트마다 컬럼 migrate 하고 적재 로직 N개를 고칠 필요가 없다.
- 단일 출처: "이 종목 어느 시장?"의 답은 `stock_master` 하나다.

**팩트의 market 처리 규칙:**

| 상황 | 처리 |
|------|------|
| 새 팩트 테이블 | **market/country 컬럼 신설 금지. `stock_master` JOIN.** |
| market 컬럼 없는 팩트의 시장 필터 | 컬럼 추가 ❌ → 읽기 쿼리에서 `stock_master` JOIN. 스키마 무변경 |
| `stock_investor_flow.market` | **레거시 의도적 denormalization** — movers 일별 전종목 스캔 핫패스용. 정본 아님(차원에서 파생). 보존하되 이 패턴을 더 확산하지 않는다 |

**진짜 멀티컨트리 시 후속 마이그레이션**(미국 실적재 시점에만, 미리 하지 않는다): 현 팩트들은 KRX 코드로 키를 잡고 `'KR:'||stock_cd` 로 master 에 다리를 놓는 KR 하드코딩 구조다. 미국을 적재할 땐 팩트가 country 중립 키 `stock_master.stock_key` 를 직접 들어야 같은 JOIN 이 NASDAQ/US 를 무수정으로 반영한다.

## KOFIA 원본·집계

| 테이블 | 담는 것 | 키 |
|---|---|---|
| `kofia_data` | KOFIA 원본 일별 팩트. 숫자는 **원(won) 단위**(조/억 변환은 프론트) | `(date, config_name, company)` |

| `kofia_agg` | 월말·연말 사전집계. **모든 분석의 기반** | `(period_type, period, config_name, company)` |

- **완전성 불변식**: 적재는 (date, config) 응답 1건을 단일 executemany + commit 으로 원자 처리한다 → **소계 행 존재 = 그 config·그 날짜 완전 적재**. 기준일 해석은 이 불변식 위에 서 있다(함수 계약은 `db/DB.md`). 무조건 `MAX(date)` 를 쓰면 부분 수집일이 기준일로 잡혀 stale 혼합과 정합 오판을 만든다.
- **새 집계를 추가할 때 `kofia_data` 를 직접 GROUP BY 하지 않는다** — `kofia_agg` 경유. agg 는 원본 저장 시 해당 월/연이 자동 갱신되고, 데이터 정정 후에는 전체 재구축이 따로 있다.

**AUM 계층 (⚠️ 중복 계산 금지)**

```
전체 AUM = 공모 + 사모 + 일임
공모 AUM = ETF + 기타공모      ← ETF가 공모에 포함 (단순 additive 아님)
공모_non_etf = 공모.합계 - ETF.합계
```

**저장 타입은 소스 정밀도가 정한다** — 게이트 ⑭(`static_check_schema.py`)가 `db/schema_*.py` 에서 강제한다.

- `REAL`(float4)은 쓰지 않는다. 가수 24비트라 **2^24 = 16,777,216 초과 정수를 표현하지 못한다**. 비율·점수라도 `DOUBLE PRECISION` 을 쓴다 — 4바이트 아껴서 얻는 것이 없고, "이건 비율이니 괜찮다"는 예외 판단이 매번 끼어드는 것 자체가 새는 지점이다.
- 원 단위 금액은 `DOUBLE PRECISION` 이다. 정수 정확 범위가 2^53(약 9,007조원)이라 AUM 을 여유 있게 담는다. `NUMERIC` 은 psycopg2 가 `Decimal` 로 돌려줘 기존 float 산술을 깨고, `BIGINT` 은 JSON→JS 에서 어차피 float64 로 붕괴해 이득이 없다.
- `NUMERIC(p,s)` 의 스케일은 **소스를 실제로 확인한 사람만** 정한다. 같은 줄에 근거 주석을 남기지 않으면 게이트가 막는다.

**Config Naming** — 일반은 `{category}_{region}_{basis}`(`전체_국내_NAV`), ETF 만 예외로 `ETF_{region}` 이고 basis 는 항상 NAV 다. 파싱은 `(category, basis, region)` 순서로 반환한다.

**소계 상수** (정본 `constants.py`) — 일반 소계는 `"자산운용- 소계"` 로 **하이픈 뒤 공백**이 들어가고, ETF 소계만 `"합계"` 로 다르다. 비교군은 주요 5사에 삼성·미래에셋·한국투자신탁운용을 더한 8개사다.

- **`kofia_nm` 매핑이 회사 차원의 존재 이유**다. 경영공시는 금감원 코드 체계, 수탁고는 KOFIA 회사명 체계라 두 세계를 잇는 다리가 이 컬럼 하나뿐이다.

## ETF 온톨로지

온톨로지는 **구조 레이어**(주 1회 리밸런싱되는 뼈대)와 **속성 레이어**(노드에 붙는 일별 측정값·분류)로 나뉜다.

| 레이어 | 테이블 |
|---|---|
| 구조 | `etf_pykrx_map`(활성 ETF 코드) · `etf_pdf`(ETF → 종목 편입 비중, 주 1회) · `etf_detail`(ETF NAV·메타, 매일) · `etf_brand_map`(이름 prefix → 운용사, 수동) |
| 속성 | `etf_investor_flow`(ETF 일별 수급) · `stock_investor_flow`(전종목 일별) · `stock_sector`(KRX 업종) · `stock_master`(종목 정본 차원) |

- **LEFT JOIN 원칙**: 구조 레이어를 주도형 JOIN, 속성 레이어를 보조형 LEFT JOIN 으로 연결한다. 속성 데이터가 없어도 구조는 정상 렌더링되고 NULL 은 프론트가 시각 폴백한다.
- **종목 정본 차원 = `stock_master`** — `stock_key` 는 국내가 `'KR:'+krx_cd`, 해외는 `'OV:'+정규화명` placeholder 다.
- ⚠️ **`etf_pdf.stock_cd` 로 종목을 식별하지 말 것**: 해외 종목에서 한 코드에 32종목까지 충돌하는 placeholder 다. `(stock_cd + 종목명)` 을 종목 차원과 대조해 `stock_key` 를 채우고, 노드 dedup·label·섹터는 **stock_key 기반**으로 한다(업종 동기화 선행 필요).
- ⚠️ **pykrx 수급 컬럼명 함정**: ETF 수급 반환 df 의 기관 컬럼명은 **`"기관"`** 이다. 종목 순매수 API 의 investor *요청 인자* `"기관합계"` 와 혼동 금지(반환 컬럼 ≠ 요청 인자). `"기관합계"` 로 파싱하면 기관 순매수가 항상 None 이 된다.
- ⚠️ **순매수 기준일 함정**: 최신 영업일은 **시세만 먼저 들어오고 순매수는 미수집인 날이 있다**(적재 시차). `MAX(bas_dt)` 단일 스냅샷으로 순매수를 읽으면 전부 NULL 이 된다 → 순매수 집계는 **`MAX(bas_dt) WHERE foreign_net IS NOT NULL`** 기준일을 쓴다. 과거값을 포함하는 시계열 함수는 영향 없다.
- **섹터 결정 우선순위**: 주식은 KRX 업종 → 비주식은 자산유형(채권·파생기타·현금RP 를 테마로) → 미분류와 해외주식은 `"기타"`.
- **region 토글이 존재하는 이유**: 노드 수 차이의 대부분은 **해외(`OV:`) 편입종목**이다. 국내는 KRX 유니버스 배경이 상수인데 해외는 배경이 없어 그 운용사 ETF 가 담은 종목만 노드가 된다(회사별 천차만별, 렉 주범).
- **테마 맵의 `theme_covered`**: 선택한 테마 종목을 min_weight 이상 담았는가로 ETF·운용사를 색/회색 구분한다. "이 테마에 누가 꽂혔고 누가 비었나"를 보는 축이라 커버리지 공백이 회색으로 남는 게 기능이다.
- **속성 추가 절차**: ① 도메인 `schema_*.py` 의 MIGRATE 항목에 `ALTER TABLE … ADD COLUMN IF NOT EXISTS` ② 쓰기 upsert 에 컬럼 추가 ③ 수집 배치에 API 호출 추가 ④ 읽기 SELECT 절에 컬럼 추가 ⑤ 프론트 노드 색·지배흐름 계산 확장.

### ETF 테마 클러스터

| 테이블 | 담는 것 |
|---|---|
| `etf_theme_cluster` | ETF → 테마 클러스터 자동 매핑 + 자산군/카테고리/테마 3계층. 배치가 **1일 1회 전체 재생성** |
| `etf_theme_cluster_override` | 관리자 수동 정정. **배치 불가침** — 조회 시 LEFT JOIN + COALESCE 로 override 우선 |
| `etf_theme_rules` | 테마 키워드 규칙. 종목 데이터로 안 잡히는 테마를 보강(코드 하드코딩 탈피) |
| `etf_theme_kw_override` | 테마명 **표시 별칭**. 관리자 정정이 어드민 트리와 시장 계층에 함께 반영 |

- ★ **그룹핑 키는 원본 `theme_kw` 를 유지하고 표시 필드만 별칭**으로 바꾼다. 그룹핑까지 별칭으로 하면 동명 별칭이 의도치 않게 병합된다.
- ⚠️ **원본 무변경 원칙**: 클러스터링은 ETF 메타·편입종목 원본을 **읽기만** 하고 결과를 별도 테이블에 적재한다. 원본은 절대 수정하지 않는다.
- ⚠️ 클러스터 머지 CTE 가 읽기 모듈 **2곳에 독립 정의**돼 있고 플레이스홀더 스타일까지 drift 했다(positional vs named). 코드 통합은 백로그 — 한쪽만 고치면 화면이 갈린다.

## 증시 동향(/equity) — 전종목 시장 데이터 정본

> `/equity` 는 KOSPI/KOSDAQ 전 상장종목 시장 데이터가 베이스다. 우리 보유(ETF 편입) 오버레이는 폐기됐다 — 이 화면은 "시장 판단 + 기회 포착" 관점이라 보유 여부와 무관하다.

| 테이블 | 담는 것 |
|---|---|
| `stock_investor_flow` | **전종목 일간 시계열 정본** — 순매수·시총·시세·밸류·외인보유 |
| `equity_index` | 지수 OHLCV + 밸류. 코스피·코스닥·코스피200과 업종지수 |
| `equity_market_flow` | 시장 12투자자 풀분해 순매수 |
| `equity_short` | 전종목 공매도 잔고와 당일 거래 비중 |
| `equity_breadth` | 시장폭 precompute — 상승/하락 종목수비, 이동평균 상회 비율, 신고저 |

- ⚠️ **`stock_investor_flow` 는 두 배치가 서로 다른 컬럼 집합을 채운다** — 순매수·시총은 pykrx 배치, 시세·밸류·외인보유·market 은 equity 배치. 겹치지 않으므로 충돌이 없고, equity 쪽 upsert 는 **순매수·시총을 SET 절에서 제외해 보존**한다. 이 분업을 깨면 한쪽이 다른 쪽을 지운다.
- ⚠️ **공매도 0 은 유효값**(공매도가 없었다는 사실)이라 **0으로 저장한다**. 0%인 대형주를 NULL 처리하면 무결성 결손 오탐이 난다. 파서에 `zero_as_none` 을 켜지 말 것. 공매도는 KRX **T+2** 제공이라 미제공일은 skip 한다.
- ⚠️ **시장폭의 이동평균·신고저는 종목별 룩백이 부족한 초기 구간에서 NULL** 이다(워밍업). 결손이 아니다.
- ⚠️ **지수 밸류는 per-code 호출**로 받는다. 전지수 1콜 API 는 이 pykrx 버전의 버그를 밟는다.
- ⚠️ **pykrx 한글 컬럼은 버전마다 다르다** — 모든 수집기가 후보명을 받는 헬퍼로 방어한다.
- **시세 read 기준일** = `MAX(bas_dt WHERE close IS NOT NULL)`(비거래·미수집 NULL 행 회피).
- **시장 필터**는 위 차원 원칙대로 `stock_master` JOIN 이 정본이다. 읽기 함수는 `market: str | None = None`(None = 시장통합 하위호환)을 받고 라우트가 값을 검증한다.
- **백필 자가복구**: 최근 N영업일의 종가 적재 종목수가 인접 거래일 중앙값의 50% 미만이면 결함일로 판정해 그 날을 통째로 재수집한다.

## 매크로 (FRED·CFTC·ECOS·KOSIS)

| 테이블 | 담는 것 |
|---|---|
| `macro_series` | **다국가·다소스 시계열 long-format**. 차원 컬럼은 country/source/freq, 값은 원시 레벨 |
| `cot_positioning` | CFTC COT 주간 포지셔닝(상업/비상업 net 과 비중) |

- **차원 단일테이블 결정**: 나라별 테이블 분리 대신 한 테이블에 country/source/freq 차원을 뒀다. 근거는 ⓐ 쿼리가 series_id 시크라 차원 컬럼 유무가 속도와 무관하고 ⓑ "미국 vs 한국 사이클 비교"가 핵심이라 JOIN/UNION 없이 유리하며 ⓒ 멀티컨트리 확장이 row 추가로 끝나기 때문이다. 수억 행에 도달하면 country 리스트 파티셔닝으로 코드 무변경 전환한다(지금은 YAGNI).
- ⚠️ **일별 채권 시리즈는 월별 게이지 시리즈와 네임스페이스를 분리한다.** 같은 series_id 에 일별을 섞으면 z-score 가 오염된다. 스프레드(bp)는 저장하지 않고 읽기에서 계산한다.
- ⚠️ **CFTC 응답 컬럼은 축약형**이다(풀스펠 아님). 잘못 쓰면 예외 없이 NULL 이 적재된다.
- ⚠️ **FRED 결측은 값이 `"."`** 으로 온다 — 적재에서 제외한다.
- **신용 스프레드 프록시**: FRED 신용 OAS 는 라이선스 때문에 2023 중반부터만 제공돼 백필이 불가하다 → HYG/IEF·LQD/IEF **ETF 가격비율**을 위험선호 프록시로 대체한다(분자·분모 종가의 날짜 교집합).
- **FRED 증분 = series 별 MAX 의 최솟값**: 전체 MAX 만 보면 한 series 만 몇 주 결측이어도 since 가 오늘이라 그 갭이 영구 미복구된다. 일·주·월간이 섞여 있어 가장 뒤처진 월간 series 발표일까지 since 가 당겨지고, 일별 series 가 매일 재요청되지만 전부 멱등 upsert 라 무해하다.
- **수집 가시화(silent swallow 방지)**: 개별 series 실패는 `failed` 목록에 모으고 배치는 계속 돈다. 0행이면 batch_log status 를 error, 실패가 일정 수 이상이면 partial 로 남긴다. 예전엔 success 고정이라 결손이 조용히 지나갔다.
- **한국 월별 지표는 실시간이 아니다** — 산업활동 약 5주, 경상수지 약 2개월 발표 시차. **사이클 국면(top-down 레짐) 분석용**이다. 원천 기관코드는 수집 설정 dict 안에만 두고 **DB·API 에 노출하지 않는다**(series_id 는 의미 기반).

## 애널리스트 리포트

`analyst_reports` 는 증권사 종목분석 리포트 팩트이고, LLM 이 추출한 stance/thesis/catalysts 가 같은 행에 붙는다.

- **자연키는 `url`** — 멱등 upsert 앵커(뉴스 기사 관례).
- **증분**: 네이버는 url 에서 파싱한 nid 최대값 초과 건만 상세를 방문한다. 목록은 매번 재스캔하되 멱등 upsert 라 누락이 self-heal 된다.
- **한경 메타 보강**은 `(stock_cd, publish_date, firm)` 매치로 목표가·투자의견을 덮어쓴다. **firm 표기가 다르면 미매치 → 같은 리포트가 두 건으로 보일 수 있다**(데이터 유실은 아님, 별칭 보정으로 대응).
- **LLM 소급 큐**: 부분 인덱스(stance NULL & 요약 있음)가 큐다. 실패는 stance 를 NULL 로 남겨 다음 배치가 소급한다. 분석 저장 시 목표가·의견은 COALESCE 로 한경 메타를 유지한다.
- **차원 원칙**: 시장·종목명 정본은 `stock_master` JOIN. 팩트인 리포트에 market 을 denormalize 하지 않는다.
- `llm_prompts` 는 prompt_key 로 도메인을 늘리는 공용 테이블이다. 행이 있으면 관리자 수정본이 우선, 없으면 git 시드 MD 를 쓴다.

| 테이블 | 담는 것 |
|---|---|

## 내부 수탁고 스냅샷

> 수기 엑셀 업로드 전용(배치 없음). T+1 일별.

| 테이블 | 담는 것 |
|---|---|
| `internal_fund_snapshot` | **행단위 팩트** — grain 은 `기준일 × 운용펀드 × 판매사`. 원본 엑셀 컬럼 전부 보존 |
| `internal_fund_org_map` | **관리 계층 매핑 차원**(부문 ▸ 본부 ▸ 구분). 화면 표시용 |
| `internal_fund_division_renames` | 구분명 변경 등록부 **겸 업로드 정규화 치환표** |

- ⚠️ **`fee_income_ytd`(기간 보수수익) = 연초부터 기준일까지 누계(YTD)** 라 말일 스냅샷 컬럼들과 성격이 다르다. 수탁고가 소멸(NAV 0)했는데 연중 기수취 보수가 남은 행은 정상이다. **0 을 NULL 로 변환 금지**([[feedback_zero_is_valid_not_null]]). 델타는 NAV 에만 계산한다(누계 차감은 연도 경계 리셋 처리가 필요해 스코프 밖).
- **델타 3종 앵커**: 전일은 달력 전일이 아니라 **직전 스냅샷**, 전주는 −7일 이하 최근, 전년은 전년말 이하 최근이다. 앵커 스냅샷이 없으면 null 이고 UI 는 앵커일을 병기한다.
- **멱등 전량 교체**: 자연키가 없어 같은 기준일 재업로드는 DELETE → INSERT 다. 운용펀드가 빈 행(수식만 남은 잔여행)은 skip 한다.
- ⚠️ **적재 전에 rename 등록부로 구분명을 정규화**한다. 안 하면 과거 날짜 엑셀을 다시 올릴 때 구 구분명이 조용히 부활한다(감지 표면이 어드민 화면뿐이라 늦게 발견된다).
- **구분명 변경 승계**는 한 트랜잭션에서 과거 스냅샷 rewrite, 매핑 PK 이관, 등록부 기록·평탄화를 함께 한다. 같은 기준일에 구·신 이름이 **공존**하면 이름 변경이 아니라 병합이므로 거부한다(422).
- **미등재 안전망**: 매핑에 없는 구분은 **숨기지 않고** `미분류` 말단으로 노출한다(조용한 누락 방지). **매핑은 숨김 수단이 아니다** — 화면 숨김은 별도 메커니즘이 담당하며 **집계는 불변**이다(표시 리스트에서만 빠지고 합계는 전량 기준).
- ⚠️ **접근 가드**: 조회 API 는 임직원 OTP 세션 가드, 업로드 API 는 어드민 가드다. **구 공유키 + 쿼리스트링 해제 방식은 폐기됐다 — 옛 문서·코드를 근거로 열쇠 게이트를 되살리지 말 것**(정본 `dept_issues/DEPT_ISSUES.md`).
- **market/종목 차원 무관**: 내부 관리 스냅샷이라 `stock_master` JOIN 규칙이 해당 없다. 본부·부서·판매사가 늘어도 row 추가로 끝난다.

## 영업 현황 보드

> 도메인 정본 `dept_issues/DEPT_ISSUES.md`.

| 테이블 | 담는 것 |
|---|---|
| `dept_master` | **본부 차원** — 부문·정렬·비활성·참고 본부·마케팅 별도 표기명 |
| `issue_board_hidden_values` | 보드 표시 숨김 값(구분·마케팅 구분). **이슈와 무관** — 이름만 `issue_` |
| `issue_board_display_order` | 마케팅 구분 표시 순서(배열 index 전량 교체). 위와 동일하게 이슈 무관 |
| `member_login_codes` | OTP 로그인 코드. 사번 PK — 이메일은 개인 매칭이 불확실해 폐기했다 |

- **본부 차원을 따로 둔 이유**: 수탁고 조직 매핑은 엑셀 조직 한정이라 조직 차원으로 부적합하다(수탁고 밖 조직도 보드에 나온다). 이름이 일치할 때만 수탁고 실측이 자동 연동된다.
- ★ **두 테이블 동기 규칙**: 본부 차원과 조직 매핑은 **한 트랜잭션 전량 교체**가 편집 정본이다. **개별 테이블을 따로 교체하는 API·UI 를 다시 만들지 말 것** — 양쪽 독립 편집이 이름 drift 를 유발해 폐지했다. 본부명 변경은 전용 경로로만 하고, 두레이 프로젝트 매핑까지 같은 트랜잭션에서 이관해야 경영 보고가 보드에서 실종되지 않는다.
- ⚠️ **신규 시각 컬럼 추가 시 `ALTER … ADD COLUMN` 에 DEFAULT 를 두지 말 것.** DEFAULT 를 붙이면 기존 행이 전부 마이그레이션 시각으로 채워져 백필이 무의미해진다. 컬럼을 먼저 만들고 `UPDATE … WHERE … IS NULL` 로 값을 채운다.
- **이슈 카드 3테이블(`dept_issues`·`dept_issue_comments`·`dept_issue_edit_logs`)은 폐기**됐다(2026-07-29 기능 전면 제거). 코드에서 DDL·읽기·쓰기를 전량 제거했고, 서버 잔존 테이블 DROP 은 `scripts/migrations/004_2026_07_29_drop_dept_issues.sql` 을 백업 후 1회 수동 실행한다.
- **AI 경영 보고서 테이블도 폐기**됐다(경영 보고는 두레이 미러 단일 경로). **서버 DB 의 테이블·행은 잔존한다** — 비파괴 원칙이고 DROP 은 사용자 지시가 있을 때만 마이그레이션으로 한다.
- **OTP 로그인은 4번째 접근 패턴**이다(무인증·공유키·어드민 세션 외 신설). 서명 시크릿이 없으면 fail-closed 다.

| `dooray_project_exposure` | **화면 노출 설정 + 소속 매핑**(본부·마케팅 구분 택1, CHECK). 수집 대상 설정이 아니다 |
| `dooray_task_overrides` | 어드민 표시 override(제목·본문·숨김/고정) **+ 업무 단위 소속**(본부·마케팅 구분 택1, CHECK) |

- **왜 미러인가**: 두레이가 원본이고 우리 DB 는 읽기 사본이다. 수정은 두레이에서 하고 다음 크롤이 반영한다. **어드민 override 를 별도 테이블에 둔 이유**가 여기 있다 — 크롤은 미러 테이블만 전량 upsert 하므로 수정본이 재크롤에 지워지지 않는다. override 적용분은 화면에 "관리자 수정"을 표기해 출처 왜곡을 막는다.
- **삭제 의미론이 업무와 댓글에서 다르다**: 업무는 마킹만 해 과거 보고 이력을 남기고, 댓글은 크롤 범위 안에서 전량 교체해 두레이에서 지운 댓글이 화면에 남지 않게 한다. 댓글은 업무에 종속이라 이력 가치가 없다는 판단이다.
- **수집 ≠ 노출**: 크롤은 서비스 계정이 속한 프로젝트를 전부 돌고 신규 프로젝트를 **기본 미노출**로 등재한다. 초대가 곧 수집 시작이지만 어드민이 켜기 전까지 사용자 화면엔 안 뜬다.
- **소속 매핑이 노출의 두 번째 조건**: 보드가 본부·마케팅 구분 축이라 소속이 없으면 업무를 놓을 자리가 없다 → **미매핑 프로젝트는 어디에도 안 뜬다**(조용한 누락이 아니라 확정 규칙, 어드민에 안내 병기). ⚠️ **댓글 쿼리에도 같은 조건**을 걸어야 미노출 업무의 진행 경과가 페이로드로 새지 않는다.
- ⚠️ **본부명과 마케팅 구분명은 별개 이름공간**이라 같은 문자열이 양쪽에 존재할 수 있다. 조회 반환을 한 map 으로 합치면 조용히 섞인다 — 소유 차원별 map 2개로 낸다. 본부는 `rename_dept`, 마케팅 구분은 `rename_marketing_dept`(참조 이관)가 매핑을 옮긴다.
- **소속은 두 층이다** — 프로젝트 매핑이 기본, 업무 override 가 예외다. **override 에 값이 있으면 프로젝트 소속을 레코드 단위로 통째 대체**한다(필드별 COALESCE 는 택1 불변식을 깬다). 해석 정본은 `dept_issues/dooray_tasks.py` 의 `resolve_task_owner` 하나이고 SQL 게이트와 **통과 ⇔ non-null 동치**다. 노출 토글은 프로젝트 단위로 남는다.
- ⚠️ **override 의 소속이 크롤에 안 지워지는 근거는 "크롤의 삭제 = 마킹"** 이다. 이 테이블은 `task_id` FK 가 `ON DELETE CASCADE` 인데 크롤은 `removed_at` 을 마킹만 하고 부모 행을 물리 삭제하지 않는다. **크롤 경로를 물리 삭제로 바꾸면 업무 단위 소속 매핑이 조용히 증발한다.**
- **물리 삭제는 어드민 프로젝트 퍼지 하나뿐**이다(`delete_project`). 두레이에서 프로젝트를 지우면 크롤 순회에서 아예 빠져 `removed_at` 마킹조차 못 받고 영구 잔존하는데, 그 상태를 끊는 유일한 경로다. 자동화하지 않는 이유는 "라이브 목록에 없음"이 *프로젝트 삭제*와 *서비스 계정 멤버 이탈*을 구분하지 못해서다 — 후자를 삭제로 처리하면 멀쩡한 미러가 통째로 날아간다.
  - 지우는 순서가 계약이다: **리비전 → 업무 → 노출 설정**. 리비전만 FK 가 없어 CASCADE 를 못 타므로 부모보다 먼저 지우지 않으면 고아만 남고 되찾을 단서(`project_id`)도 함께 사라진다.
  - 라이브 판정은 **서버가 다시 한다**. 두레이 조회 실패는 fail-closed 로 막는다 — 장애와 삭제를 구분 못 하는 상태에서 되돌릴 수 없는 작업을 실행하지 않는다.
- ⚠️ **소속 ALTER 는 `_DOORAY_TASK_OVERRIDES_MIGRATE`(init_db 동기 트랜잭션)에 둔다.** `_DOORAY_TASKS_INDEXES` 는 백그라운드 스레드 큐라 lifespan yield 이후에 돌고, 루프 전체가 단일 try/except 라 앞선 인덱스 하나가 실패하면 뒤 ALTER 가 통째로 스킵된다. 레포 관례는 **ALTER=MIGRATE(동기) / CREATE INDEX=INDEXES(백그라운드)** 다.
- ⚠️ **빈 결과 함정**: 서비스 계정이 프로젝트 멤버에서 빠지면 두레이는 에러가 아니라 **200 + 빈 목록**을 준다. 그대로 반영하면 전 업무가 소실 마킹되므로, 기존 행이 있는데 빈 결과가 오면 스킵하고 경고한다. 페이지 순회 중 예외도 그 프로젝트를 통째로 스킵한다 — **부분 목록으로 삭제 마킹 금지**.
- **표시 제외는 read 레이어 단일 정본**이다(수집에서 거르지 않아 규칙이 바뀌어도 재크롤 없이 복원된다). 우선순위는 **두레이 삭제 → 무조건 숨김**(고정도 못 이김) > 수동 숨김 > 수동 고정 > `!` 로 시작하는 제목 > 완료 후 유예 경과.
- **완료 시각은 자체 스탬프**다 — API 가 완료 시각을 주지 않아 크롤이 전이를 처음 본 시점을 기록한다. 완료 유지 중에는 COALESCE 로 보존해야 하고(재크롤마다 갱신되면 유예가 영원히 안 온다), 완료 해제 시 NULL 로 리셋한다. **여기서도 ALTER DEFAULT 금지** — 기존 행이 마이그레이션 시각으로 오염되면 유예 판정이 통째로 어긋난다.
- **리비전은 변경분만 append** 한다. 기한 비교는 API 문자열과 DB datetime 을 aware 로 맞춘 뒤 한다 — 표기 차이를 변경으로 오인하면 매 크롤이 이력을 쌓는다. 보존 정책은 미구현(증가율이 낮음).
- **타임스탬프**: 두레이 응답은 UTC 와 KST 오프셋이 혼재하지만 그대로 TIMESTAMPTZ 에 넣는다(Postgres 가 오프셋을 해석). 우리가 찍는 수집 시각만 KST aware 다.
- **상위·하위업무(`parent_task_id`, 2026-07-31)**: 두레이 `parent.id` 미러. 최상위는 NULL. **`parent` 가 목록 응답에도 실려 와 추가 API 호출이 없다.**
  - ⚠️ **FK 미지정**이 의도다 — 목록이 등록 역순이라 자식이 부모보다 먼저 upsert 되는 순서가 실제로 나오고, 부모 삭제는 행 제거가 아니라 마킹이라 CASCADE 도 무의미하다. 고아는 read 레이어가 최상위로 흡수한다.
  - ⚠️ ALTER 는 `_DOORAY_TASKS_MIGRATE`(init_db 동기)다. `_DOORAY_TASKS_INDEXES`(백그라운드 큐)에 넣으면 read 가 이 컬럼을 SELECT 하는 창에서 `UndefinedColumn` 500 이 난다. `closed_seen_at` 이 INDEXES 에 있는 건 그 관례가 서기 전의 잔재라 따라하지 말 것.
  - ⚠️ **증분 스킵분 되싣기(`get_tasks_for_reuse`)에 이 컬럼이 빠지면 계보가 매 크롤마다 NULL 로 덮인다** — upsert 가 `EXCLUDED` 로 통째 갱신하기 때문이다.
- **완료일 기간 조회 인덱스(2026-08-04)**: 업무 기록 탭이 `closed_seen_at` 으로 자른다. `WHERE workflow = 'closed'` 부분 인덱스라 전체 행 수와 무관하게 작다 — 진행중은 기간을 안 타므로 담을 이유가 없다. 조회는 `(closed_seen_at AT TIME ZONE 'Asia/Seoul')::date` 로 캐스팅한다(세션 타임존에 기대면 9시간 밀려 월 경계 업무가 옆 달로 넘어간다).

## 미국 산업 사이클

> 도메인 정본 `us_cycle/US_CYCLE.md`. `industry` 단위는 GICS Sub-Industry(멤버 3 이상).

raw 3종(일별 수정종가, 펀더 시점 스냅샷, 재무 income statement)과 주간 스냅샷 3종(산업, 경기국면, 종목)으로 나뉜다. 매크로 게이지는 위 `macro_series` 를 재사용하고 별도 수집하지 않는다.

- **bottom-up 롤업 재설계**: 종목별 3요소를 자기 이력 기준으로 계산해 산업으로 롤업한다. **업종 간 횡단 z-score 는 폐기**했다 — 구조적 고PER 산업에 편향이 생겼다.
- ⚠️ **펀더는 이력이 없는 시점 스냅샷**이다(yfinance `.info`). 그래서 **애널리스트 컨센서스만** 횡단면에 쓰고 나머지는 이력 보유 테이블에서 계산한다.
- **데이터 기간**: 가격은 2015~, 밸류·KPI 재무는 2021~(연간 5년). 이 때문에 사이클 시계열은 풀스코어 **실선**과, 밸류·애널 부재 구간을 모멘텀·52주위치 2요소로 근사한 **점선**이 겹쳐 그려진다.
- **종목 스냅샷은 사전계산 저장**이다 — 산업 롤업이 계산하고 버리던 종목별 값을 저장해 드릴다운이 가격 풀로드 없이 SELECT 로 소비한다. 롤업이 쓴 값 그대로라 산업 점수와 정합한다.
- ⚠️ **SSL**: yfinance 는 curl_cffi 백엔드라 공용 requests 패치가 무효다. 수집 모듈이 세션을 직접 주입한다(상세는 도메인 MD).

## '기타' 처리 원칙

- `"기타"` 는 DB 에 실제 데이터로 존재하고 시장 합계(소계)에 포함된다.
- **UI 선택지(드롭다운 등)에는 노출하지 않는다** — 운용사 단위 분석에서 의미 없는 잔여 항목이다.
- 소계는 **항상 첫 번째 기본 옵션으로 유지**한다.
- 회사 목록 필터링 시 제거 대상은 `"기타"` 뿐이다(소계는 별도 옵션으로 제공).
