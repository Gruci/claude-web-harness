대표 검수 루프 — 브리핑·대시보드·지표를 `ceo-reviewer` 에이전트가 검수하고, 피드백을 반영해 재작업·재검수를 반복한다.

> 담는 것: 검수 → 보완 → 재검수 루프의 진행 방식과 종료 조건. 담지 않는 것: 검수 기준과 대표 페르소나(→ `.claude/agents/ceo-reviewer.md`). 읽는 시점: 대표 검수·CEO 리뷰 요청 시.

## 트리거 조건
- "대표 검수 돌려줘", "CEO 리뷰"
- 브리핑 내용이 실제로 의미 있는지 확인 요청
- 새 대시보드/지표 추가 후 비즈니스 관점 검증
- "이 지표들이 맞는 건지 봐줘"

## Phase 1: 검수 대상 확정

검수 가능한 대상:
- **브리핑 텍스트**: AI가 생성한 인사이트 문장·요약
- **지표 목록**: 대시보드·테이블에 표시되는 항목 나열
- **화면 설명**: 레이아웃·섹션 구성·정보 위계 기술
- **복합**: 위 여럿을 한꺼번에

검수 대상을 명확히 정리한 후 Phase 2 진행.

## Phase 2: ceo-reviewer 에이전트 호출

`ceo-reviewer` 에이전트에 아래 형식으로 전달:

```
[검수 요청]
유형: <브리핑 텍스트 / 지표 목록 / 화면 구성 / 복합>
내용:
---
<검수 대상 원문 또는 상세 설명>
---
추가 컨텍스트: <관련 배경 (예: 이 화면은 peers 비교 페이지, 월간 이사회용 브리핑 등)>
```

## Phase 3: 피드백 분류 및 작업 배정

ceo-reviewer 출력의 판정에 따라:

| 판정 | 다음 액션 |
|------|---------|
| 승인 | 루프 종료, 결과 보고 |
| 조건부 승인 | ⚠️ 보완 필요 항목만 수정 후 Phase 4 |
| 반려 | ❌ 누락 + ⚠️ 전체 재작업 후 Phase 2 재진입 |

**보완 작업 배정**:
- 지표·UI 수정 → 메인 루프가 직접 (다수 파일 독립 병렬이면 Agent 위임)
- 브리핑 텍스트 재생성 → 브리핑 생성 로직 수정

## Phase 4: 재검수

수정 완료 후 Phase 2 재진입. 변경 내역을 컨텍스트에 명시:

```
[재검수 요청]
이전 판정: 조건부 승인
반영한 수정:
- (수정 내용 1)
- (수정 내용 2)
내용:
---
<수정 후 내용>
---
```

## 종료 조건

- ceo-reviewer가 "승인" 판정 시 루프 종료
- 3회 반복 후에도 "반려" 유지 시: 사용자에게 에스컬레이션 — 근본적인 방향 재설정 필요 가능성 있음

## 주의사항
- ceo-reviewer는 코드 품질 검수 안 함 — 비즈니스 의미·지표 완결성만 평가
- 피드백 없이 "좋아요" 판정 나오면 에이전트 프롬프트 재점검
- 브리핑 특성상 같은 내용 2회 이상 반려 시 지표 설계 자체를 재논의할 것
