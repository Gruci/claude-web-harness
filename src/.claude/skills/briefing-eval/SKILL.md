# briefing-eval — 브리핑 골든셋 회귀 평가

> 담는 것: 골든 대비 후보 프롬프트 산출물을 비교해 배포 가부를 판정하는 절차. 담지 않는 것: 브리핑 프롬프트의 내용과 변경 절차(→ `market_briefing/MARKET_BRIEFING.md`)·검수 페르소나(→ `.claude/agents/ceo-reviewer.md`). 읽는 시점: 시황 브리핑 프롬프트를 고친 뒤 배포하기 전.

> 프롬프트를 고쳤을 때 **산출물이 실제로 좋아졌는지**를 배포 전에 확인하는 유일한 절차.
> `market_briefings.sources` 가 기사 원문(lead·body)을 전량 보존하므로 과거 입력을 100% 복원해
> 같은 입력·다른 프롬프트로 A/B 를 돌릴 수 있다.

## 실행 절차

1. **재분석**: `python scripts/briefing_eval.py` (초안 검증이면 `--prompt-file <초안.md>`,
   특정일이면 `--dates 2026-07-20,2026-07-21`) → 마지막 줄의 산출 디렉토리 경로 확보.
   DB 는 건드리지 않는다(`set_report` 미호출) — 저장된 리포트는 골든으로 그대로 남는다.
2. **기계 비교 확인**: 산출 디렉토리 `summary.md`. 후보 생성 실패(None)가 1건이라도 있으면
   더 볼 것 없이 **"회귀: 파싱 실패"** 판정 후 종료.
3. **정성 비교**: 날짜별로 `ceo-reviewer` 에이전트를 호출한다. golden/candidate JSON 경로를 주고
   아래 프롬프트를 그대로 사용:

   ```
   [비교 검수 요청]
   같은 입력(기사·시장 실측치)으로 생성된 두 시황 리포트다.
   A=현행(골든), B=후보 프롬프트 산출물.
   B가 A 대비 ①정보 누락 ②수치/인용 정확성 저하 ③의사결정 연결성 약화 가 있는지 항목별로
   대조하고, 최종 판정을 [개선/동등/회귀] 중 하나 + 근거 3줄로 답하라.
   문체 취향 차이는 회귀가 아니다.
   ```

4. **집계**: 회귀 ≥1건 → **"배포 보류 + 회귀 사유"** 보고. 전건 동등/개선 → "배포 가능" 보고.
5. **기록**: 판정 요약을 산출 디렉토리 `verdict.md` 로 저장하고, 사용자에게는 결과만 보고한다.
   `prompt_snapshot.md`(sha256 + 전문)가 그 산출물을 만든 프롬프트의 유일한 버전 기록이다 —
   DB 는 생성 시점 프롬프트를 저장하지 않는다.

## 주의

- `claude -p` 실비용이 대상 날짜 수만큼 발생한다(기본 최신 5건, `--limit` 로 조절).
- 기사 전문이 들어간 큰 프롬프트라 1건에 수십 초~수 분 걸린다. 타임아웃(analyzer 300초)으로
  실패하면 후보가 None 이 되므로, 전건 실패면 회귀가 아니라 환경 문제일 수 있다 — 재실행으로 구분.
- 산출 디렉토리는 gitignore 대상(`docs/tasks/briefing_eval/`) — 판정 결과만 커밋/보고에 남긴다.

## 근거

- 실사고: 프롬프트 지침 2줄 추가가 실제 산출물을 안 바꿨는데 배포됨.
  "로컬 1회 수동 실행"으로는 변화 유무를 판정할 수 없었다 → 골든 대조가 정본 절차가 됐다.
- 프롬프트 변경 절차 정본: `market_briefing/MARKET_BRIEFING.md`
