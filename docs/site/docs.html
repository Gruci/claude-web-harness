MD 라우팅 지도

이 레포에서 MD는 읽을거리가 아니라 작동 규칙이자 장기 기억이다. 세션마다 새로 들어온 내가 무엇을 언제 읽는지가 이 지도로 정해지고, 도달할 수 없는 MD는 게이트가 고아로 잡아낸다.

MD가 하네스인 이유

코드에 적용하는 유지보수성 기준을 MD에도 그대로 적용한다. 이유는 하나다 — 둘 다 다음 세션의 행동을 결정하기 때문이다.

읽힘routing
CLAUDE.md가 세션 시작 시 자동 주입되고, 그 라우팅표가 "이 작업에는 저 MD를 먼저 Read하라"를 지시한다. @ import가 아니라 on-demand Read라서 필요한 것만 컨텍스트에 올라온다.
강제gate ④
경로 참조 실존(④A), 배치표 대조(④B), .env 키 대조(④C), 고아(④D), 하네스 지도(④E)를 기계가 검사한다. MD 한 줄만 고쳐도 이 다섯이 통째로 돈다.
감사/md-audit
게이트가 못 잡는 의미 서술의 부패는 월 1회 사람 판단으로 잡는다. 전수감사에서 26개 MD에 91건이 나온 이력이 이 주기의 근거다.

허브 구조

고아 판정(④D)의 시드가 되는 여섯이다. 모든 정본 MD는 이 중 하나에서 링크를 타고 도달 가능해야 한다.

작성 3원칙과 성분 판정

정본은 dev/MD_STANDARD.md다. 게이트 ⑬이 이 규칙 중 기계 검사 가능한 부분만 강제한다.

#원칙한 줄 정의
①가독성한 줄·문단·섹션 = 한 의미 단위. 사람이 훑어서 판단할 수 있어야 한다
②연결성한 사실은 한 곳에만, 다른 곳엔 링크. 모든 MD는 허브에서 도달 가능해야 한다
③잡동사니 배제grep으로 알 수 있는 것은 적지 않는다

성분 판정 — 무엇을 담고 무엇을 안 담나

코드성분정본MD에
A파일 목록 · 디렉토리 트리ls / Glob❌
B시그니처 · props · 타입 · 엔드포인트 목록코드❌
C소비처 · import · 호출 그래프Grep❌
D변경 이력 · 삭제 기록 · 날짜 태그git log❌ (dev/LESSONS.md만 예외)
E라우팅 · 계약 · 함정 · 결정 근거MD 뿐✅
F도메인 지식 — 스키마 의미 · 업무 규칙 · 외부 API 특성MD 뿐✅

경계 판정 시험 — "이 줄을 지우면 다음 세션이 잘못 행동하는가?"

  • 파일명 나열이어도 절차 계약이면 E다. 예: 새 테이블은 DDL 추가 → schema import → init 호출 순서.
  • 시그니처여도 재사용 지시면 E다. 공용 헬퍼 레지스트리는 "재구현 금지"가 본체다.
  • 날짜와 근거가 붙어 있으면 날짜만 D다. 이유는 남기고 날짜는 뗀다.
  • 수치 임계값은 코드가 정본이다. MD엔 왜 그 값인지만 남긴다.

판정 테스트

"이 MD의 한 가지를 고치려면 무엇을 다시 써야 하나?" 한 줄만 = 양호 / 한 절 재작성 = 정리 필요 / 파일 통째 재작성 = 갓 함수. 코드였으면 리뷰에서 반려될 물건은 MD에서도 반려다.

머리 역할 계약 — 게이트 ⑬d가 강제한다

모든 정본 MD는 첫 인용구에 이 세 항목이 있어야 한다. 없으면 위반이다.

> 담는 것: {이 파일이 담당하는 것}.
  담지 않는 것: {다른 곳 소관}(→ 링크).
  읽는 시점: {언제 이걸 열어야 하나}

경계 — 안 읽는 것

읽을 것만큼 안 읽을 것도 규칙이다. 경계를 넘으면 다른 하네스의 규칙을 이 하네스에 섞게 된다.

web/templates/ · web/admin/templates/편집 금지레거시 UI. PostToolUse 훅이 차단한다. 이식·롤백 참고는 Read와 git 이력으로

공유 정본 — 양쪽 하네스가 함께 쓰는 것

Codex와 Claude Code가 공유하는 문서다. 고칠 때 한쪽만 생각하면 안 된다.

README.md · PRODUCT.md · DEVGUIDE.md · DESIGN_GUIDE.md · dev/ · design/ · 도메인별 MD · static_check.py

새 MD를 만들면 같은 턴에 허브 등재 라우팅표에 행을 추가하지 않으면 읽힐 타이밍이 없고 게이트 ④D가 고아로 잡는다. 도메인 동명 MD만 총칭 라우팅으로 자동 인정된다.

라우팅의 정본은 CLAUDE.md·DEVGUIDE.md·DESIGN_GUIDE.md 세 허브의 표이고, 작성 규칙의 정본은 dev/MD_STANDARD.md다. 이 페이지는 2026-08-04 시점의 사본이다.
