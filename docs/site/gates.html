include_md가 켜지는 조건은 둘이다. 전체 모드로 실행했거나, 단일 파일 모드에서 대상이 .claude/·docs/ 밖의 .md일 때. 이 6개는 파일 하나가 아니라 레포 전체를 훑는다.

⑬만 등급이 둘이다 check_md_style()은 (hard, soft) 두 리스트를 돌려준다. hard는 섹션 위반으로 합산되고 soft는 [REPORT]로 찍히기만 한다. 그래서 [REPORT]가 여러 줄 떠 있어도 종료가 막히지 않는다.

게이트별 판정 방식

"어떻게 잡아내는가"다. 판정 방식이 정규식인지 ast인지에 따라 우회 가능성과 오탐 양상이 갈린다.

번호판정 방식예외 수단
1줄 수 카운트. 대상은 git ls-files *.py 중 실존 파일없음
2ast 파싱 — 함수 안의 def 노드scripts/·docs/ 경로
3정규식 CREATE|ALTER|DROP TABLE|INSERT INTO|UPDATE|DELETE FROM + .commit(없음
4정규식 ^\s*net\s*= — 지역변수 단독 할당만dict 키 *_net은 애초에 미검출
4b정규식 \b(oper|rev)_\w레거시 web/static·web/templates·scripts·docs
5문자열 포함 검사 — UI_DENYLIST 리터럴리스트에 없으면 통과. 새 조어는 사람이 추가
⑩정규식 [:\[,]\s*Any\b · ->\s*Any\bANY_ALLOWLIST 4파일 · # any-ok: 사유
⑪정규식 :\s*any\b · as any · <any. 주석 줄은 건너뜀// any-ok: 사유
④A백틱 안 경로 토큰 추출 후 실존 확인. 루트·frontend/src·MD 자기 디렉토리 기준으로 해석하고 tracked 전량에 접미 매칭md_ref_allowlist.txt · docs/·idea/·memory/ 접두
④Bast로 batch_runner.py 최상위 int 상수 수집 → DEVGUIDE.md 표의 (*_HOUR 참조와 시각 대조없음
④Csettings.py의 os.getenv 키 ↔ DEVGUIDE 목록 양방향 diffKRX_ID·KRX_PW (pykrx가 직접 로드)
④D허브 6개를 시드로 MD 링크 그래프 BFS. 백틱 경로와 마크다운 링크 양쪽을 간선으로 인정도메인 동명 MD는 무조건 도달로 인정 · .codex/·.agents/ 제외
④Esettings.json 커맨드에서 .py|.mjs|.md 토큰 추출, agents/*.md stem, skills/*/SKILL.md 부모 디렉토리명을 모아 HARNESS.md 본문에 문자열 포함 확인없음. 단 단방향이라 지도에만 남은 항목은 미검출
⑬b인라인 코드를 걷어낸 뒤 ·로 갈린 조각 중 15자 이상인 것을 셈. 6개 초과면 위반코드명만 나열한 줄은 조각 길이가 짧아 자동 통과
⑬dfrontmatter 제외 후 머리 12줄 안에 > 담는 것: … 담지 않는 것: … 읽는 시점: 패턴docs/·.agents/·.codex/·impeccable·/prompts/·EDITING.md
⑯origin/main 대비 diff — 프롬프트 본문이 바뀌었는데 첫 줄 V<major>.<minor>가 그대로면 위반origin/main이 없는 얕은 클론은 검사 생략
정규식 게이트의 한계를 알고 쓴다 ⑩·⑪·4b 같은 정규식 게이트는 문자열만 본다. 타입 별칭을 만들어 우회하면 안 잡힌다. 게이트를 통과시키려고 이름을 비트는 것이 바로 CLAUDE.md가 "게이트 게이밍"이라 부르며 금지한 행위다. 게이트는 하한선이고, 판단은 여전히 사람과 리뷰의 몫이다.

게이트 추가 절차

검사 가능한 규칙이 새로 생겼을 때 밟는 순서다.

  1. 정의 위치를 고른다. 기존 모듈이 400줄에 여유가 있으면 거기, 아니면 새 static_check_<주제>.py를 만든다. static_check.py와 static_check_gates.py는 둘 다 399줄이라 더 못 받는다.
  2. 검사 함수를 쓴다. 시그니처는 (files: list[Path]) -> list[str]. 반환은 "경로:줄: 사유" 문자열 목록이다.
  3. 섹션에 등록한다. static_check.py의 _build_sections()에 ("번호+이름", 모듈.함수(files)) 한 줄. 이 한 줄이 static_check.py를 정확히 400줄로 채운다 — 그 다음 게이트부터는 등록 전에 파일 분리가 먼저다.
  4. 기존 위반을 센다. 많으면 baseline 파일이나 모듈 내 BASELINE 튜플로 동결하고, 같은 커밋에서 잠근다.
  5. HARNESS.md 게이트 표에 행을 추가한다. 번호·검사·정의 파일·예외 네 칸이다.
  6. 돌려서 확인한다. python static_check.py가 exit 0이어야 세션이 끝난다.
순서를 지키는 이유 4번을 건너뛰면 새 게이트가 기존 코드 수십 건을 한꺼번에 [FAIL]로 띄우고, 그 세션은 Stop 훅에 막혀 끝나지 못한다. 동결 없이 게이트를 켜는 것은 자기 발을 묶는 것이다.

정본은 static_check.py 헤더 docstring과 각 모듈이다. 등재 수치는 2026-08-04 실측이라 시간이 지나면 어긋난다 — 세려면 python static_check.py를 직접 돌린다.
